# R0 任务书：采集 + 归一化 + 去重

> 本任务书交给 Codex 实现。完成后由 Claude 质检，逐条核对「验收标准」，全部通过才进入 R1。

## 目标

从数据源抓取新闻 → 归一化成统一结构 → SQLite 去重 → 落盘原始 JSON。

**本阶段不接入 LLM、不写 Obsidian、不做筛选分类**（筛选分类在 R1，概括在 R2，归档在 R3）。

## 需要实现/新增的文件

在现有骨架基础上，新增以下文件：

```
src/
├── models.py                  # 共享 Item 数据类（后续 R1-R3 复用，勿改字段名）
├── config_loader.py           # 读取 config/*.yaml 的统一入口
├── fetch/
│   ├── rss.py                 # RSS 采集
│   ├── hn.py                  # Hacker News 采集
│   └── normalize.py           # 归一化 + id 生成
└── scheduler/
    ├── dedup.py               # SQLite 去重（SeenDB）
    ├── log.py                 # 日志初始化
    └── run.py                 # R0 主入口
```

## 统一 Item 结构（src/models.py）

用 `@dataclass` 定义，字段如下（全部必填，允许空串，字段名不可改）：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | str | 稳定唯一 id = `md5(url)` 的 hex |
| title | str | 标题 |
| url | str | 原文链接 |
| summary | str | 源自带摘要（可空） |
| source | str | 来源名，如 `TechCrunch`、`Hacker News` |
| source_type | str | `rss` 或 `hacker_news` |
| published_at | str | ISO8601，可空 |
| author | str | 作者，可空 |

序列化用 `dataclasses.asdict`，写入 JSON。

## 各文件职责

### src/fetch/rss.py
- `fetch_rss(feeds: list[dict]) -> list[dict]`：遍历 `sources.yaml` 的 `rss_feeds`，用 `feedparser` 抓取。
- 每个 entry 提取 title / link / summary / author / published。
- **单个源失败**（超时/解析错误）要 `try/except`，记日志后继续下一个源，不允许整体崩溃。

### src/fetch/hn.py
- `fetch_hn(cfg: dict) -> list[dict]`：抓 `topstories` 前 `max_items` 条，逐条 GET item。
- 只保留 `type == "story"` 且未 `deleted` / `dead` 的。
- 提取 title / url / text / by / time。
- `url` 为空时用 `https://news.ycombinator.com/item?id={id}` 兜底。

### src/fetch/normalize.py
- `normalize(raw: dict, source_type: str, source: str) -> Item`
- 统一时间：RSS 的 `published_parsed` → ISO8601；HN 的 unix 时间戳 → ISO8601；解析失败置空串。
- `make_id(url) -> md5 hex`。
- RSS 的 `summary` 需去掉 HTML 标签（用 `feedparser` 的 summary 字段或简单正则）。

### src/scheduler/dedup.py
- `SeenDB(db_path)` 类，封装 `sqlite3`。
- 表结构：
  ```sql
  CREATE TABLE IF NOT EXISTS seen (
      url_hash TEXT PRIMARY KEY,
      url TEXT NOT NULL,
      source TEXT,
      first_seen TEXT NOT NULL
  );
  ```
- `is_new(item) -> bool`：查 `url_hash` 是否存在；不存在则 insert 并返回 True；存在返回 False。
- 提供 `close()` / `commit()`。

### src/scheduler/log.py
- 用 `logging` 初始化，日志写入 `logs/`（按天滚动），级别读 `config.yaml` 的 `log.level`。

### src/config_loader.py
- 用 `yaml.safe_load` 加载 `config/config.yaml` 和 `config/sources.yaml`，返回配置对象/字典。

### src/scheduler/run.py（R0 版）
1. 读 config + sources。
2. 依次 fetch rss + hn → normalize → 去重。
3. 去重后 items 写入 `data/raw/YYYY-MM-DD.json`（当天日期，时区 `Asia/Shanghai`）。
4. 打印统计：各源抓取数、去重数、最终保留数。
5. 全程 try/except，单源失败不中断整体。

## 配置读取（不要硬编码路径/密钥）

- `data.raw_dir`、`dedup.db_path`、`log.dir`、`log.level` 从 `config.yaml` 读。
- `rss_feeds`、`hacker_news.*` 从 `sources.yaml` 读。
- 运行入口：`python -m src.scheduler.run`。

## 验收标准（质检逐条核对）

1. `pip install -r requirements.txt` 成功后，`python -m src.scheduler.run` 能正常跑完。
2. 生成 `data/raw/<当天日期>.json`，内容是 Item 数组，字段齐全。
3. 连续运行两次，第二次同一 URL 被去重跳过，统计里能体现 skipped 数量。
4. `state/seen.db` 生成，表结构正确。
5. 日志写入 `logs/`。
6. 某源断网/挂掉时，其它源照常抓取，程序不崩溃。
7. 代码不依赖任何 `requirements.txt` 之外未声明的第三方库。

- 不硬编码 API key / 路径 / 模型名。
