# R1 任务书：智能筛选 + 分类（DeepSeek）

> 本任务书交给 Codex 实现。完成后由 Claude 质检，逐条核对「验收标准」，通过才进入 R2。

## 前置条件（实现前必须先确认）

R1 是**首次接 LLM**，需要你先在 `config/config.yaml` 里确认/填写，否则无法联调：

1. `llm.model` —— 以账号实际可用模型名为准（默认 `deepseek-v4-flash`）
2. `llm.base_url` —— 官方 `https://api.deepseek.com` 或你的自建/代理端点
3. 环境变量 `DEEPSEEK_API_KEY` —— 运行时从 `llm.api_key_env` 指定的环境变量读取

## 目标

读取 `data/raw/<日期>.json` → 批量调 DeepSeek → 判断相关性 + 归类 → 输出 `data/classified/<日期>.json`。

**只做分类，不做概括总结**（概括总结是 R2）。

## 需要新增的文件

```
src/classify/
├── deepseek_client.py   # DeepSeek 调用封装（OpenAI 兼容 + JSON mode + 重试）
├── prompt.py            # 构造 system/user prompt（注入词表）
└── classify.py          # R1 主逻辑，可独立运行
```

## 输入 / 输出

**输入**：`data/raw/<日期>.json`（R0 产出的 Item 数组）。无日期参数时读当天（`Asia/Shanghai`）的文件。

**输出**：`data/classified/<日期>.json`，每条记录 = **原 Item 全部字段 + 分类字段**（合并，供 R2 直接消费）：

```json
{
  "id": "...",
  "title": "...", "url": "...", "summary": "...",
  "source": "...", "source_type": "...", "published_at": "...", "author": "...",
  "relevant": true,
  "company": ["OpenAI"],
  "category": "技术突破",
  "segment": ["AI模型·大模型"],
  "importance": 4,
  "reason": "一句话理由"
}
```

- 输出**所有**条目（含 `relevant: false`），便于质检过滤质量；R2 只消费 `relevant: true` 的条目。
- `company` 取自观察清单（可多个；不在清单但明显是重要科技公司可填具体名；不相关留 `[]`）。
- `category` 从 `taxonomy.yaml` 的 categories 单选；`segment` 从 segments 多选；`importance` 为 1-5。

## 各文件职责

### src/classify/deepseek_client.py
- 用 `openai` SDK 的 `OpenAI(api_key=..., base_url=...)` 连 DeepSeek（OpenAI 兼容）。
- `api_key` 从 `os.environ[config["llm"]["api_key_env"]]` 读，base_url/model 从 config 读，**禁止硬编码**。
- 用 `response_format={"type": "json_object"}` 保证输出 JSON。
- 带重试（次数取 `llm.max_retries`），失败记日志；单个 batch 失败不中断整体（跳过该 batch 并记录，继续下一个）。
- 暴露 `classify_batch(items: list[dict], vocab: dict) -> list[dict]`。

### src/classify/prompt.py
- 从 `watchlist.yaml` 提取**公司名平铺列表**；从 `taxonomy.yaml` 提取 categories、segments。
- 构造 system prompt（含分类规则 + 词表）与 user prompt（含待分类 batch）。
- 规则要点：relevance 判断「是否属于美国优秀科技公司的重要消息」，噪音（八卦/无关/纯招聘/重复营销）判 false；company/category/segment 只能从给定词表选。

### src/classify/classify.py（主逻辑，`python -m src.classify.classify`）
1. 读 config + sources + watchlist + taxonomy。
2. 读 `data/raw/<日期>.json`。
3. 按 `batch_size`（默认 25，可配置）分批，逐批调 `classify_batch`。
4. 将 LLM 结果按 `id` 对齐合并回原 Item，输出合并记录。
5. 写 `data/classified/<日期>.json`。
6. 打印统计：总数、relevant 数、irrelevant 数、各 category 计数。

## 验收标准（质检逐条核对）

1. `python -m src.classify.classify` 能跑完，生成 `data/classified/<日期>.json`。
2. 每条记录字段齐全（原 Item 8 字段 + relevant/company/category/segment/importance/reason）。
3. **id 对齐正确**：输入每条 item 在输出里都有且仅有一条对应记录。
4. `category` 值必须 ∈ taxonomy 的 categories；`segment` ⊆ segments（不许出现词表外的新分类词）。
5. 抽样人工检查：relevant 判断合理、归类准确率可接受。
6. 所有 LLM 参数（model/base_url/key 名）来自 config，无硬编码。
7. 单个 batch 失败不崩溃整体，有日志、有重试。

## 明确不做

- 不做概括/总结（R2）、不写 Obsidian（R3）、不做调度（R4）。
- 不硬编码 API key、模型名、base_url。
