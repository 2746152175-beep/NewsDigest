# R2 任务书：概括 + 总结（DeepSeek）

> 本任务书交给 Codex 实现。完成后由 Claude 质检，逐条核对「验收标准」，通过才进入 R3。

## 目标

对 R1 判为 `relevant` 的条目，抓取原文正文，用 DeepSeek 生成「内容概括 + 内容总结/产业启示」，输出 `data/summarized/<日期>.json`。

**只做概括总结，不写 Obsidian**（归档是 R3）。

## 前置

- 复用 R1 的 LLM 配置（`config.yaml` 的 `llm` 段，base_url / api_key_env / model / temperature / timeout / max_retries 均不变）。
- 运行时需环境变量 `DEEPSEEK_API_KEY`。

## 需要新增的文件

```
src/summarize/
├── fetch_body.py     # 抓取原文正文（trafilatura）
├── prompt.py         # 概括总结 prompt
└── summarize.py      # 主入口，可独立运行
```

## 输入 / 输出

**输入**：`data/classified/<日期>.json` 中 `relevant == true` 的条目（跳过 irrelevant）。

**输出**：`data/summarized/<日期>.json`，每条 = 原分类记录全部字段 + 概括字段：

```json
{
  "...原 Item 8 字段 + 分类字段...": "...",
  "summary": "内容概括（客观：这条新闻讲了什么）",
  "insight": "内容总结/产业启示（主观：意味着什么、对产业趋势分析的价值）",
  "key_points": ["要点1", "要点2"]
}
```

## 各文件职责

### src/summarize/fetch_body.py
- 用 `trafilatura` 抓 `item.url` 正文（`trafilatura.extract(...)`）。
- 正文截断到 3000 字符；抓取失败或为空返回空串（概括时 fallback 用 `item.summary`）。
- 单个 URL 失败 `try/except`，不中断整体。

### src/summarize/prompt.py
- system prompt：你是科技产业分析师，对每条新闻产出三样 —— `summary`（客观概括）、`insight`（产业启示）、`key_points`。
- 要求中文输出；`summary` 客观不评价；`insight` 要结合产业趋势、竞争格局、技术影响。
- user prompt：给定 title、来源、发布时间、原文正文（或摘要）。

### src/summarize/summarize.py（主入口 `python -m src.summarize.summarize`）
1. 读 `classified/<日期>.json`，过滤 `relevant == true`。
2. 逐条 `fetch_body` 抓正文（失败 fallback 到 `item.summary`）。
3. 按 `batch_size`（默认 8）分批调 LLM，产出 summary / insight / key_points。
4. 合并回原记录，写 `summarized/<日期>.json`。
5. 打印统计：relevant 数、概括成功数、正文抓取成功数。

## 验收标准（质检逐条核对）

1. `python -m src.summarize.summarize` 能跑，输出 `data/summarized/<日期>.json`。
2. 只处理 `relevant == true` 的条目，输出条数 == relevant 数。
3. 每条 `summary` 与 `insight` 非空且为中文。
4. 正文抓取失败的条目仍能生成概括（用 RSS summary 兜底）。
5. **id 对齐**：relevant 的 id 全在输出、无重复。
6. 抽样检查：`summary` 客观、`insight` 有产业视角，两者不混。
7. 不硬编码，只用已声明库（trafilatura、openai、pyyaml + 标准库）。

## 明确不做

- 不写 Obsidian（R3）、不做调度（R4）。
- 不硬编码 API key / 路径 / 模型名。
