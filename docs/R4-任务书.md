# R4 任务书：调度 + 增量 + 收尾

> 本任务书交给 Codex 实现。完成后由 Claude 质检，这是最后阶段。

## 目标

把 R0–R3 串成一个每日主入口，加定时调度，并收尾之前质检积累的小问题。

## 需要新增/修改

### 1. 主入口编排（改造现有 `src/scheduler/run.py`）
- 把 `run.py` 从「只跑 R0」改为「串起 R0→R1→R2→R3」。
- 计算当天日期**一次**，用 `--date <日期>` 传给每个阶段（各阶段 `main` 已支持 `--date`）。
- R0 的抓取逻辑从 run.py 抽出成一个函数（如 `run_fetch(config, date)`），保留在 scheduler 模块内。
- R1/R2/R3 通过 `from src.classify.classify import main as ...` 导入其 `main` 并调用（传 `["--date", date]`）。
- 阶段间有依赖：R1 失败则跳过 R2/R3（因为 R2 依赖 R1 的 classified 输出），R2 失败则跳过 R3；每阶段失败记 ERROR 日志、打印清晰的分阶段统计。

### 2. 定时调度
- 项目根目录新增 `run_daily.bat`：cd 到项目根、设 `DEEPSEEK_API_KEY`、调用 `D:\工作区\软件\Python312\python.exe -m src.scheduler.run`。
- README 增加「每日定时」小节：给出 Windows 任务计划程序 `schtasks /create ...` 命令示例（每天定时跑 `run_daily.bat`），工作目录与日志都指 D 盘。

### 3. 收尾修复（质检积累，逐一落实）
a. **R0 normalize 解码 HTML 实体**：标题/摘要用 `html.unescape` 处理，消除 `&#8217;` 等残留（改 `src/fetch/normalize.py`）。
b. **config 补全**：`llm.timeout` 60→120（推理模型慢）；补显式 `llm.retry_backoff: 2.0`、`classify.batch_size: 25`、`summarize.batch_size: 8`。
c. **（可选）R1 失败批次持久化**：把「批次失败」的条目 id 存到 `state/failed_batches.json`，下次运行重试；本次至少要做到「失败批次有明确 ERROR 日志」。不强制。

## 验收标准（质检逐条核对）

1. `python -m src.scheduler.run` 一键跑通 R0→R1→R2→R3，最终产出到 vault。
2. 各阶段失败有日志、有合理的中断策略（不无脑继续）。
3. `run_daily.bat` 存在，路径全 D 盘、内容正确。
4. 新抓取数据的标题不再出现 `&#8217;` 等 HTML 实体。
5. `config.yaml` 里 `timeout: 120`、`retry_backoff`、`classify.batch_size`、`summarize.batch_size` 显式存在。
6. 只写 D 盘；不引入新依赖（标准库 + 已声明库）。

## 明确不做

- 不新增第三方依赖。
- 不在 C 盘创建任何文件（含任务计划程序的工作目录、日志）。
- 不改 R1/R2/R3 已验收的核心逻辑（只允许新增调用入口、不许改动其算法）。
