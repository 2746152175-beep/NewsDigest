# R6 任务书：数量滑块 + 领域勾选 + 低价值过滤

> 分两轮：R6-a 后端过滤 + 配置，R6-b 前端控件。每轮独立验收。

## 目标

新增两个控制（数量滑块、领域勾选）+ 两个过滤（重要性阈值、相似去重），减少数量、限制领域、过滤低价值，提高响应速度。

## 设计决策（已定稿）

- 数量滑块：`fetch.max_items`，默认 60，范围 10–200，R0 去重后按发布时间取前 N。
- 领域勾选：`filter.segments`（空 = 不过滤），勾选后只保留这些领域（R2 输入过滤）。
- 重要性阈值：`filter.importance_min`，默认 3，只保留 importance ≥ 阈值的。
- 相似去重：标题归一化 + difflib 相似度 > 0.8 判重，保留 importance 最高的一条。

---

## R6-a：后端过滤逻辑（本轮）

配置数据（taxonomy.yaml 25 领域、watchlist.yaml 重归类、config.yaml 的 fetch/filter 段）已由 Claude 写好，Codex 只做代码逻辑：

1. **数量限制**：`src/scheduler/run.py` 的 `run_fetch`，去重后按 `published_at` 降序排序（空值最后），取前 `fetch.max_items` 条。
2. **过滤 + 相似去重**：`src/summarize/summarize.py` 的 relevant 过滤扩展为：
   - `relevant == true`
   - `importance >= filter.importance_min`
   - `filter.segments` 非空时，`segment` 与选中集合有交集
   - 相似标题去重（`difflib.SequenceMatcher` 比值 > 0.8，归一化：小写 + 去非字母数字，保留 importance 最高）
3. **settings API 扩展**：`src/web/settings.py` + `src/web/app.py`：
   - GET /api/settings 增加返回 `max_items`、`importance_min`、`segments`（已勾选）、`all_segments`（taxonomy flat）、`groups`（taxonomy groups）
   - POST /api/settings 增加 body 字段 `max_items`、`importance_min`、`segments`，写 config.yaml 对应段

## R6-a 验收标准

1. `python -m src.scheduler.run` 仍能跑通。
2. `fetch.max_items` 改小后，R1 只处理 ≤ N 条。
3. `filter.segments` 设 1 个领域后，R2 只概括该领域。
4. `filter.importance_min` 调大后，只保留高 importance 条目。
5. 相似去重：同一事件多来源只留 1 条。
6. settings API 能读写新字段、返回 all_segments + groups。

## 硬性约束

- 不改 R1 分类、R3 归档、前端页面（R6-b 再做）。
- 不引入新依赖（difflib 是标准库）。
- 不写 C 盘。
